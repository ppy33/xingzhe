## v1 能力总览（原始原型）

## 一句话定位

像旅行顾问一样问清关键信息（出发地/天数/同行人/偏好/禁忌），然后调用 **天气 / POI / 路线优化 / 预算 / 预订 / 安全校验** 这一整套工具，把行程排到小时，并记住你的偏好。

---

## 三入口快速开始

- **直接说需求**：「从上海出发，去成都玩 4 天，2 个人，喜欢美食和自然，不吃辣，节奏轻松」
- **点示例**：左侧 7 个目的地 chip（上海/北京/广州/西安/三亚/昆明/东京）任选
- **看架构**：右侧「架构」标签，10 层能力成熟度面板 + Agent 循环图

## 已实现能力（按 10 层模型）

| # | 能力层 | 状态 | 说明 |
|---|---|---|---|
| 1 | 用户理解与个性化 | ✅ done | 槽位抽取（预算/时间/出发地/同行人/语言/无障碍）+ 长期记忆 |
| 2 | 多模态交互 | 🟡 part | 文字+语音输入+拍照识别（演示模板匹配）+语音导览；情感/紧急转人工 |
| 3 | 行前规划 | ✅ done | 需求澄清→目的地知识→行程生成→预算测算→预订入口→清单提示 |
| 4 | 行中服务 | 🟡 part | 导航示意/通勤时长、动态重规划、讲解朗读、紧急资源 |
| 5 | 行后与社交 | ⚪ road | 行程归档导出已实现；多人投票/分摊未实现 |
| 6 | 数据与知识层 | 🟡 part | POI/气候/汇率/紧急信息带来源；实时库存与排队为模拟 |
| 7 | 技术架构 | ✅ done | Agent 编排+工具调用+运筹优化（k-means 聚类+最近邻+开放时间约束）+记忆库 |
| 8 | 生态与工具集成 | 🟡 part | OTA/Booking 深链入口；真实库存需开放 API+商务协议 |
| 9 | 安全合规可信 | ✅ done | 记忆可查可删、来源标注、估算显式声明、SOS 与人工兜底 |
| 10 | 商业与评估 | 🟡 part | 任务完成率/延迟/工具调用/成本/幻觉自检已埋点；转化留存需线上数据 |

## 数据覆盖

- **示例 POI 库**：101 个 POI / 7 个城市（上海/北京/广州/西安/三亚/昆明/东京）
- **未覆盖城市**：自动降级为通用模板并明确标注，不假装认识当地具体景点
- **实时数据**：浏览器调用 `node server.js` 后通过 `http://127.0.0.1:8787` 接入

---

## 工具链（Agent 循环每轮走一遍）

```
意图理解 → 槽位补全 → 知识检索 → 工具调用 → 结果校验 → 运筹优化 → 安全兜底 → 记忆写回
```

任一环节异常都会回落到「安全兜底 → 人工客服」，不把不确定结果直接抛给用户。

## 生产架构替换路径（许涵松的预留设计）

| 模块 | 当前（原型） | 生产（替换目标） |
|---|---|---|
| LLM 层 | 规则引擎 | 意图/槽位/回复 → function calling |
| 工具层 | 内置模拟 | weather/poi/route/price/booking → 真实 API |
| 记忆层 | localStorage | 向量库 + 关系库，跨设备 + 可删除 |
| 优化层 | k-means + 最近邻 | OR-Tools VRPTW（带时间窗的车辆路径） |
| 实时层 | 轮询模拟 | 事件流（航班/天气/场馆状态）→ 主动服务 |
| 兜底层 | SOS 弹窗 | 独立通道，不经过模型 |

## 如何本地启动

```bash
# 离线模式（默认）：双击打开 行者.html 即可
open 行者.html

# 实时数据模式：启动后端 server（许涵松提供 server.js）
node server.js
# 然后浏览器访问 http://127.0.0.1:8787
```
